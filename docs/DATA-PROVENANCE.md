# Data provenance

## Purpose and safety boundary

The public demo contains only deterministic synthetic records. It does not
connect to a public SQL database at runtime, copy source rows, or preserve
names, addresses, identifiers, transaction descriptions, documents, account
numbers, individual compensation, or other source-level values.

The standard scenario is generated by
`src/demo-data/scenario.ts`. The same seed and anchor date always produce the
same graph of synthetic entities. The reference configuration is:

- Scenario version: `2`
- Seed: `management-platform-standard-v2`
- Anchor date: `2026-07-01`
- Generated payload SHA-256:
  `c42a65f8372a1614b1a18e50bc8b8b5953093aa0a75c3b2f8f2131176bb63d34`
- Verified on: `2026-07-27`

## Reference sources

### Microsoft AdventureWorks

- Publisher: Microsoft
- Source:
  <https://github.com/microsoft/sql-server-samples/tree/master/samples/databases/adventure-works>
- License: MIT, as declared in the repository root
- Reference version: repository `master`, documentation reviewed
  `2026-07-23`
- Local source artifact: none
- Source artifact checksum: not applicable; no database backup, SQL file, row
  or source archive is included or processed by this repository
- Transformation: the optional offline adapter accepts only four caller-
  supplied aggregates: department count, product-category count, order count
  and median order-line count. It emits bounded ratios used to calibrate the
  size of a completely new synthetic graph.
- Attribution: “AdventureWorks sample database, Microsoft; MIT license.”

### Instituto Nacional de Estadística (INE)

- Publisher: Instituto Nacional de Estadística, Spain
- Source: <https://www.ine.es/datosabiertos/>
- License: Creative Commons Attribution 4.0 International, as declared on the
  INE Open Data page
- Reference version: public Open Data landing page reviewed `2026-07-23`
- Local source artifact: none
- Source artifact checksum: not applicable; no table, microdata file or API
  response is included or processed by this repository
- Transformation: the optional offline adapter accepts only a reference
  period and three aggregate indices. It reduces them to a bounded monthly
  economic-variation coefficient. No individual or geographic record can pass
  through the adapter.
- Attribution: “Aggregate statistical reference: Instituto Nacional de
  Estadística (INE), CC BY 4.0.”

## Offline adapter contract

`src/demo-data/calibration.ts` validates aggregate-only inputs with Zod. Every
input must include a source version, observation date and SHA-256 checksum of
the external artifact reviewed by the operator. Source artifacts stay outside
this repository. Strings that could carry names, addresses or free-form source
rows are not part of either adapter contract.

The application uses `createDefaultCalibration()` unless a reviewed aggregate
profile is supplied during an explicit offline generation step. Production
never downloads or queries AdventureWorks or INE.

## Standard scenario coverage

The current standard scenario contains:

- 32 fictional people across 6 operating teams, represented by deterministic
  initials
- 12 naturally named projects
- 320 tasks, 79 acyclic dependencies and 319 comments
- 144 leave requests across an 18-month window
- 240 incidents with service, scope and detection context
- 720 imported treasury entries with positive monthly cash flow
- 24 aggregate payroll cycles
- 36 editorial changelog entries
- More than 3,000 related records including immutable activity and trace data

Names are natural fictional combinations from the local synthetic catalog. Connector labels are
`Financial Source A`, `Financial Source B`, `Payroll Master` and
`People Master`. None refers to an employer, bank, payroll product or real
provider.

## Reproduction

```powershell
bun run demo:data:generate
bun run demo:data:validate
bun run demo:data:report
```

`demo:data:seed` requires the explicit `--local` flag embedded in the package
script. At this stage it prepares and validates the local seed payload but does
not contact a remote project. Remote seeding remains a separately reviewed
deployment operation.

## Size controls and retention

The target is to keep each public-demo workspace well below the Supabase Free
database quota. Supabase documents that Free projects enter read-only mode at
the 500 MB database-size quota:
<https://supabase.com/docs/guides/platform/database-size>.

The planned retention job removes inactive demo workspaces after 90 days. It
must be enabled only after its SQL, dry run and Cron schedule have been
reviewed against the deployed project.
